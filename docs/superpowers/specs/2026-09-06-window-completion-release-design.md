# Nopin 窗口完成检测修复与 v1.0.2 发布

## 已确认的范围

用户已同意：只修复窗口完成通知缺失时的排队等待，保留当前 UI、原生动画和 300 ms 测试标准，补齐回归测试后发布 v1.0.2。保留已有的 v1.0.1 标签，不移动或覆盖旧版本。

本次不修改 Notion 连接、数据处理、密钥存储、品牌图标或其他界面行为。仍仅发布 macOS 13+ 的 Apple Silicon 和 Intel DMG，不使用 Developer ID 签名或 Apple 公证。

## 证据与边界

- 两次原生 Intel 发布测试在连续第六次收起/展开时失败，响应分别为 496.5 ms 和 399.9 ms。
- 当前控制器在收不到 `resized` 完成事件时固定等待 1000 ms。隔离模拟中，每 850 ms 发起一次请求，可复现逐次累积的排队延迟，即使窗口尺寸已经到位。
- 这证明代码存在不必要的等待路径，但尚不能仅凭现有 CI 日志断定该路径就是 Intel 失败的唯一原因；修复是否足够，仍以实际安装包复测为准。

## 最小修复设计

1. 仍由主进程窗口控制器串行管理收起/展开，不改渲染层交互或 CSS 动画。
2. 为当前请求记录目标高度。有效的原生完成事件继续正常结束请求；不能让高度尚未到位的事件提前结束请求。
3. 补充完成判断：收到窗口尺寸变化事件后，只有在高度已到达目标、并连续 100 ms 没有新的尺寸变化时，才允许补充确认完成。中间帧或新的尺寸变化会取消或重新开始这段观察。
4. 保留现有 1000 ms 最终兜底，防止没有任何有效事件时 IPC 永久等待。完成、失败和销毁时清理所有相关计时器。
5. 保留完成后 200 ms 合并保存窗口位置/尺寸的机制，不逐帧写磁盘，也不让同步保存阻塞完成回复。

选择该方案是为了修复实际请求排队。仅延长测试间隔可以帮助诊断，但不能解决用户连续点击时的等待，因此不作为此次修复。

## 验证与发布顺序

1. 先加入回归测试，确认旧代码无法通过：缺少完成事件、连续请求、中间帧、过早完成事件、销毁清理和最终兜底。
2. 实现上述窄范围修复，运行格式、静态检查、类型检查、完整单元测试和依赖审计。
3. 使用隔离配置及测试钥匙串构建、启动 Apple Silicon 安装包，运行原有动画和布局测试；不接触真实 Notion token 或用户应用配置。
4. 将版本升级到 v1.0.2，使用新标签触发 GitHub 发布。原生 Intel 安装包必须通过未放宽的 300 ms 检查及完整测试，之后才创建 Release。
5. 核对双架构 DMG、签名与磁盘镜像完整性、版本和图标、打包文件范围、校验和及公开下载地址。说明仍明确标注未签名、未公证，并保留官方打开方法。

如同一失败仍存在，继续依据日志定位；不绕过检查发布，也不把局部验证表述为所有 Mac 上均无问题。
